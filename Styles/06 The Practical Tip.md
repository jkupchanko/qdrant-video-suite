# The Practical Tip

**Use when:** One small action can be explained and demonstrated without a long background lesson.

**Audience fit:** Useful for newcomers learning a small skill and experienced viewers improving a familiar task. Choose a benefit that matches the viewer’s work.

**Funnel fit:** Discovery or action. It can support consideration when it demonstrates how an approach behaves.

**Use another structure when:** The task contains several dependent steps that each need explanation; use The Guided Process.

**Keep it accurate:** Do not promise a complete system when the video teaches only one small action.

## Questions this structure answers

1. What is the useful action?
2. How do I perform it?
3. How do I know it was done correctly?

## General layout

The times show placement in a five minute video.
The fields describe what to write and show, rather than supplying a finished script.

### 1. Hook   0:00 to 0:15

**Purpose:** Establish the task and the small result the viewer will learn to produce.

**Written hook:** Name the action or the useful result.

**Verbal hook:** Connect a familiar task to the specific improvement the video will demonstrate.

**Template:** [Small action] helps with [specific task or difficulty].

**Keep the viewer with you:** Make the promised result narrow enough to demonstrate promptly.

[**Show:** The task or a preview of the result. **Transition:** Move directly to the conditions for trying it.]

### 2. Follow up   0:15 to 0:45

**Purpose:** State the minimum preparation or condition needed.

**Template:** Before [action], check [necessary condition or material].

**Keep the viewer with you:** Give only the background required to follow the next step.

[**Show:** The relevant starting material or setting. **Transition:** Keep that starting state visible as the action begins.]

### 3. Demonstration   0:45 to 2:45

**Purpose:** Show the action in a reproducible order.

**Template:** Start with [input], perform [action] and inspect [output].

**Keep the viewer with you:** Narrate the action and its reason together.

[**Show:** The actual task, with one important detail highlighted at a time. **Transition:** Carry the same input through to its result.]

### 4. Check   2:45 to 4:25

**Purpose:** Explain what a successful result looks like and one important limitation.

**Template:** The action is complete when [observable check] is satisfied; [condition] changes its usefulness.

**Keep the viewer with you:** Let the viewer assess their own attempt rather than accepting a vague success claim.

[**Show:** The finished result beside the success condition. **Transition:** Return to the opening task.]

### 5. Next step   4:25 to 5:00

**Purpose:** Give a small use or check that follows naturally from the lesson.

**Template:** Try [action] on [relevant example] and inspect [specific result].

**Keep the viewer with you:** Close on the useful action rather than adding a new topic.

[**Show:** The action and its expected check in brief. **Transition:** Finish with the result visible.]

## Adjust the depth to the length

**One minute:** Show the task, the action and the check. Keep preparation to what is essential.

**Five to seven minutes:** Keep the full sequence and add only the explanation, demonstration and check needed for the stated goal.

**Thirty minutes:** Use the tip as one chapter inside a broader lesson. Add related tasks and their checks only when they serve the same goal.

## One example

This is an illustrative outline, not a recorded result or finished narration.

**Situation:** A team learns to name shared files so their latest versions can be found.

Hook: Show the difficulty of locating the current file.  
Follow up: State which parts of the filename matter.  
Demonstration: Rename one file using the chosen convention.  
Check: Explain how another person can identify the version.  
Next step: Apply the convention to the next shared file.
