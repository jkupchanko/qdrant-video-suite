# A Five Minute Search Demonstration

**Recommended title:** Can Spanish Search Find an English Answer?

**Recommended structure:** [The Guided Process](../Styles/09%20The%20Guided%20Process.md).

**Presentation:** A live search demonstration with brief code views and a conversational explanation.

## Who this is for

**Role:** A developer building search for people who may use a different language from the documents.

**Experience:** Familiar with basic search and Python, but new to this particular approach.

**Funnel stage:** Discovery moving toward a small trial.

**Reason to care:** Find useful passages without requiring the person searching to use the documents’ language.

**Outcome:** Understand the matching idea, follow one prepared search and know how to check a small example of their own.

**Available material:** A live search demonstration with a little code, as supplied in the brief.

The audience choice is a working recommendation based on the subject and the available footage.
The general library can also serve marketers, students and other viewers.

## Why this structure fits

The viewer can follow one question from the search box into the code and back to the returned passages.
Each step answers the next natural question: what are we searching, how could those words match, what does the code do and did the result answer the question?
That gives the technical explanation a visible purpose.

The opening uses a question the screen can resolve.
Show the language difference immediately, so the hook makes sense before naming the approach.
Keep the first live check close to the opening question.

## The hook and follow up

**Written hook:** Spanish question. English answer.

**Verbal hook:** Your search box accepts Spanish, but your documents are in English.
Can it still find the right answer?

**Follow up:** Let’s try it with three short passages and a little Python.

The hook creates a specific uncertainty.
The follow up establishes the size of the task and the material we will use to answer it.
The promise is a visible test and an understandable process.

## Five minute layout

### 1. Hook   0:00 to 0:20

Show a Spanish query beside an English passage that could answer it.
Let the viewer understand the mismatch before introducing terminology.

### 2. Preparation and follow up   0:20 to 0:50

Show three English passages and identify the one the first query should retrieve.
State that the collection and encoder are already prepared.
The viewer should know what counts as a useful result before seeing the search.

### 3. The matching idea   0:50 to 1:35

Explain one familiar pair of words using the same query and passage.
Use the article’s home and casa illustration as one brief supporting insert, then return to the demonstration’s words.
This gives the code meaning before the viewer has to read it.

### 4. A little code   1:35 to 2:35

Show how the passage and query are encoded, then how the query reaches the prepared collection.
Highlight one relevant line at a time.
Keep the query visible so the viewer does not have to remember what the code is for.

### 5. The live check   2:35 to 3:35

Run the search and inspect the actual returned passages.
Then change the question while keeping the same collection.
Explain what the outputs demonstrate and what this small check leaves unresolved.

### 6. The boundary   3:35 to 4:20

Explain why a familiar example is insufficient evidence for every subject.
Use the article’s bat illustration as the second supporting insert and name vocabulary coverage as something to inspect.
This turns a successful looking demonstration into a useful learning exercise.

### 7. A small next action   4:20 to 5:00

Give the viewer three kinds of questions to try with short passages of their own.
Finish with an observable check: whether the right passage appeared and where it ranked.
The invitation is to test and learn.

## How the sections keep moving

**Opening question:** Can the search connect these two languages?

**Question before the code:** What makes the words able to match?

**Question before the results:** Does the returned passage actually answer the question?

**Question after the results:** What changes when the wording or subject changes?

Answer each question before opening the next one.
Keep the same collection throughout the live sequence.
Use a new visual when the explanation needs a new object, action or comparison.
Leave code and results on screen long enough to inspect them.

These choices are recommendations to test in the finished video.
They do not establish a measured improvement in viewer retention.

## Camera and supporting inserts

Use four full screen face appearances: the opening, the transition into code, the beginning of the limit section and the closing.
Use a smaller presenter window in the top right at roughly 20% of the screen width during selected explanations.
Keep the same size and crop whenever that window returns.
Hide the face during code inspection, result inspection and the two article inserts.

Plan two B roll inserts: the article’s home and casa illustration and its contrasting bat examples.
The live search and code walkthrough remain the main footage.
The script includes capture blocks only at those two selected moments.
Each block names the source location, the view to capture and the spoken line it explains.

## When I would choose another structure

Use [The Problem and Breakthrough](../Styles/05%20The%20Problem%20and%20Breakthrough.md) if the central lesson is why a particular search approach misses an answer.

Use [The Comparison and Choice](../Styles/10%20The%20Comparison%20and%20Choice.md) if the viewer must choose between approaches using comparable evidence.

For the current brief, keep the guided demonstration as the main structure.
